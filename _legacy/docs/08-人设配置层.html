Decoupling / 判定与商品解耦

把「我卖什么」从判定逻辑里拆出去

现在的判定写得像「卖木工桌的判定」：代码里写着「求链接」「在哪买」这些词。 换商品还能凑合，换赛道就完全失效——做内容的账号被问「求链接」， 系统还以为来了笔生意。问题不在配置不够多，在逻辑和素材揉在一起了。 拆开之后，换商品只改素材，换赛道只改一个词表，代码一行不动。

01

原来错在哪

necessity.py 里有一行常量： COMMENT_INTENT = ("求链接", "在哪买", "价格", ...)。 看起来只是个词表，实际上它把三件事锁死了：

  • 赛道锁死。这组词只对「卖东西」有意义。做内容的账号收到「求链接」， 正确的反应是不接（我没有链接），系统却给了最高加分。
  • 商品锁死。卖课的人说「怎么报名」，卖课的人说「多少钱」—— 词表里没有就识别不到，等于换商品要改代码。
  • 阈值锁死。购买意图 0.50 不够单独过阈值，必须配合语料命中。 结果是一个还没养语料的新账号，遇到最强的购买信号也回不了。

更深一层的问题是：「什么样的评论值得回」这件事，本来跟卖什么没关系。 它是五个通用意图——想买、想问细节、要售后、纯社交、来骂人。 至于「想买」在你的行业里怎么说，那才是每个账号自己的事。

02

拆成两层

左边这一层永远不变，右边这一层每个账号一份。判定只读左边的标签， 词表由右边提供——它不知道也不关心你卖的是桌子还是课。

意图层跨行业固定
写在代码里
purchase 想买 · inquiry 问细节 · after_sales 要售后 · social 社交 · negative 骂人 五个标签，五年内大概不会变
素材层每个账号一份
写在 JSON 里
词表（你这个行业怎么表达「想买」）+ 答案库 + 风格样本 + 边界词 + 兜底策略 换商品改这里，换赛道也改这里

代价是配置多了一个 profile 段落。收益是代码里再也找不到 「求链接」这三个字——判定逻辑对任何行业都成立。

03

四种形态，对应四种默认行为

offering适用purchase 词表兜底
product 卖实物或虚拟商品 有，识别购买意向 转人工
content 做内容，不卖东西 空，不把评论当商机 转人工
service 卖时间、卖方案 有，但问的是「怎么约」 转人工
none 个人号，纯互动 空 沉默

offering 不只是个标签，validate 会用它检查矛盾配置： 标了 content 却配了购买词表，说明你一边说不卖一边在抓商机， 会把每句「求链接」都误判成意向——这比漏判更糟，因为回复内容会答非所问。

兜底策略是这次唯一新增的「行为」字段。 原来答不上来时总是进队列，现在可以选：转人工、沉默、或发一句固定话术。 个人号被问到不懂的东西，硬回一句模板反而暴露是机器，沉默更自然。
04

怎么验证它真的通用了

「通用」这个词很容易自说自话。唯一能证明的方式是： 同一批评论，两份配置，看结果差多少。差得越少，说明配置层越像装饰。

# 用电商人设和内容号人设，跑同一批 11 条评论 python persona_cli.py diff --a persona.json --b personas/creator.json
评论电商（小陆）内容号（阿木）
求链接 回复 0.90差异 沉默 0.00
承重多少 回复 0.90差异 无稿 0.60
质量怎么样啊 回复 0.70差异 沉默 0.35
6 / 嗯嗯 沉默 沉默
这个好看 沉默 0.15 沉默 0.15

11 条里 6 条结果不同。后两行相同也是对的——「6」「嗯嗯」两边都该沉默， 这恰好说明判定不是随机变的。

同一个问题，两种回答

「这个多少钱」在两边都被判定为需要回复（它被 @ 了）。但生成的结果完全不同：

配置生成结果
电商 价格我私信你说，评论区不太方便聊这个。
内容号 我这边不卖东西哈，纯拍着玩。问的人多了我再考虑做一批。
这两句话来自同一份代码、同一个引擎。 差别只在于加载了哪份人设配置。这就是「先设人设，再由人设反推回复」的实际形态—— 不是让模型猜你是干什么的，是把「你是干什么的」写成可执行的结构。
05

换商品、换赛道的实际操作

换商品（同一赛道）

改两个地方，判定代码不动：

  • knowledge —— 新商品的参数、发货、售后
  • few_shot —— 新商品该怎么答。这一栏决定像不像人

profile.intents 里的购买词表通常不用改——「求链接」「多少钱」 换成卖任何实物都成立。

换赛道

改 profile：把 offering 换成对应形态， 清空或替换 purchase 词表，调整 inquiry 的词。 代码依然不动。

新建一份

python persona_cli.py new --template creator --name 阿木 --role "做木工视频" \ --out personas/amu.json python persona_cli.py validate personas/amu.json

模板只给结构，不给成品话术。生成出来能跑判定，但给不出草稿—— 答案库和语料必须自己填，那部分没法通用。

06

哪些东西仍然不能复用

说清楚边界，免得配置层被当成万能药。

东西能不能复用原因
判定逻辑 能 「什么样的评论值得回」跟行业无关，这是这次拆出来的东西
购买词表 大致能 实物电商通用；换成「怎么报名」「怎么约」要改
语料 few_shot 不能 每个账号的说话方式不同，它决定回复像不像人
知识库 不能 产品参数、服务流程，天然是账号特定的
阈值 能沿用，要复测 跨行业可以先用默认值，但一致率必须重新测一遍
平台差异 部分 抖音和 B 站评论语态不同，逻辑可迁移，分布不代表一样

能复用的那块是最大的——判定逻辑。剩下不能复用的，本质上都是「这个账号是谁」， 那本来也不可能由代码提供。

一个反直觉的结论：配置层做得越好，越显得语料重要。 因为判定已经不用管了，剩下的质量差异全部落在「你填的这 20 句示范」上。 这也是为什么 M2 的门槛是「20 条草稿里 12 条能原样发出去」， 而不是「判定准确率」——后者是个位数百分比的提升，前者是能不能用的差别。
