Douyin Auth Without ICP

域名能绕，但绕过去之后
会撞上另一道墙

你问的这一步有解——而且不需要备案域名，也不需要服务器。 但在动手之前必须知道一件事：2025 年 2 月之后，移动应用和网站应用 已经申请不到评论权限了。域名问题解决了，权限问题还在。

2026-11-12 · 25 项新测试通过 · 授权工具已可用
01 / 直接回答

redirect_uri 不是「回调服务器」，是「浏览器要跳去哪」

这是整件事的关键认知。OAuth 授权成功后，平台做的是让浏览器跳转到一个地址， 并把 code 拼在参数里。它不要求那个地址现在能响应。

所以就算那个域名打不开、404、甚至根本不存在，浏览器地址栏里 已经写着 ?code=xxx 了。把它复制出来，本地换 token 就行。 整个过程不需要公网服务器，不需要域名能访问，也不需要备案。

唯一的前提是：那个 redirect_uri 能在开放平台后台保存成功。 这一步是否校验备案，不同应用类型不一样，下面会给判定方法。

适用范围

这个技巧对所有授权码模式的 OAuth 都成立（GitHub、Google、微信、抖音都一样）。 它的本质是把「接收回调」从机器改成人工。

代价是：code 只有 10 分钟有效期且只能用一次。 复制粘贴要快，粘错了得重新授权。

02 / 三种拿 code 的方式

从最省事到最完整

① 手动复制paste 推荐先试这个

生成授权链接 → 浏览器打开扫码 → 授权后地址栏出现 code → 整条 URL 粘回终端。

不需要服务器、不需要域名能访问、不需要穿透。三分钟能验完。

每次重新授权都要手动复制一次（令牌 15 天，refresh 后可到 195 天，不算频繁）。

② 本地回调 + 内网穿透serve

本地起一个服务接 code，用 ngrok / cpolar 映射成 https 地址填进后台。

授权完成后自动换 token，不用复制。适合反复调试。

穿透域名通常也是未备案域名，后台未必接受；穿透服务可能限速。

③ 小程序 ticketmini

小程序里调 tt.showDouyinOpenAuth 拿到 ticket，直接把 ticket 当 code 换 token。

完全不存在 redirect_uri，所以完全不存在备案问题。

要先有小程序；而且评论权限能不能批，是另一回事（见第三节）。

工具已经写好了

# 1. 生成授权链接
python douyin_auth.py url --client-key tt1234567890 \
    --redirect https://example.com/douyin/callback \
    --scope user_info,item.comment

# 2. 授权完，把地址栏整条 URL 丢进去（裸 code 也行）
python douyin_auth.py paste --client-key tt... --secret abc... \
    --code "https://example.com/douyin/callback?code=ffab5ec2&state=s1"

# 3. 看令牌还能用几天
python douyin_auth.py status

实跑 paste 成功时会打印：

识别到授权码：ffab5ec26cd9…（24 字符）

成功。
  open_id       b9b71865-fake-open-id
  有效期        还剩 15.0 天
  已保存到      token.json

粘贴格式不用挑

你粘什么都能识别
ffab5ec26cd958fd裸授权码
https://x/cb?code=ffab&state=s1整条回调 URL
" https://x/cb?state=s1&code=ffab "带引号、参数顺序不同、前后有空格

这个细节值得单独做，因为实际复制的时候人会连引号、空格、完整 URL 一起粘过来。 工具要求用户「只粘 code 那一段」，就会有人粘错，然后报参数错误， 而错误信息里看不出是粘贴方式的问题。

错误码翻译成人话

换取失败：[10007] authorization code expired
怎么办：授权码只有 10 分钟且只能用一次，重新生成授权链接再来

10007 是最常见的失败。如果没有这句提示，用户会以为是代码或配置坏了， 反复重试同一条链接——但 code 已经用掉了，重试必然失败。

03 / 比域名更前置的那个问题

评论权限，移动和网站应用已经申请不到了

这是这轮核实里最重要的发现，也是最坏的消息。它决定了「域名解决了」之后还能不能走。

抖音开放平台 2025 年发布过一条公告：《移动/网站应用部分能力权限下线/回收公告》。 原文两句： 

"平台将于 2025年2月13日 起停止接收移动、网站应用关于开通以下能力权限的申请，
并于 2025年3月13日 起，分批回收历史已开通的移动、网站应用的相应权限"

受影响列表里明确包含：
  · 互动管理(企业号)   video.comment
  · 管理视频评论       item.comment
  · 视频互动数据       data.external.item

公告的生效时间在一年半前，现在新建的移动应用、网站应用， 点「申请开通」时会发现入口已经不给新申请了。

所以「第三步最难」这个判断要改

OAuth 配置是第四难。第一难是「有没有应用可以申请」，第二难是「评论权限批不批」， 第三难是「企业资质」。域名排在第四。

先把域名搞定，然后在权限那一步卡住——这种情况最容易发生， 因为域名那一步看起来最吓人，实际上最便宜。

这里有一处文档自相矛盾，必须说明

「视频评论管理」能力详情页仍写着「准入条件：暂无准入条件，任一应用均可申请」， 并列出支持小程序、移动应用、网站应用三种类型。

但 2025-02 的公告说的是停止接收移动/网站应用的申请。两处优先信哪个？以后台实际入口为准。 控制台里「申请开通」按钮是否可点、点了之后是否报「该能力已停止申请」，一分钟能看出结果。 文档页可能是旧版没同步。

小程序这条路，有接口但标了「高级能力」

小程序侧确实有一套独立的评论接口：

项目小程序
评论列表GET /api/apps/v1/item/list_comment/
Scopema.item.comment
权限入口控制台 → 小程序应用 → 能力-用户数据能力-抖音账号数据 → 视频评论数据
授权方式tt.showDouyinOpenAuth 返回 ticket，换 /oauth/access_token/
是否要 redirect_uri不需要
能力分级高级能力
沙盒环境不支持

但官方 FAQ 里还有一句相反的话：

"企业小程序和个人小程序目前均不支持获取粉丝数、评论数据相关数据信息。
如需查看数据请在小程序控制台查看『数据中心』"

这句话说的是「数据统计」还是「评论内容列表」，从字面读不出来。 有些条目里 item.comment 又列在小程序能力下，和 ma.item.comment 不是同一个名字。

关于小程序通道的诚实结论
接口文档存在、授权方式确实不需要域名，但权限是否批得下来，只能在控制台点一次才知道。 我不能把「文档里有」说成「你能批到」——这两件事在抖音开放平台上经常不是一回事。

05 / 现在能做什么

三件事，都不需要等审核

一、把授权流程先跑通（如果手上有应用）

创建应用不需要等权限。拿到 client_key 和 client_secret 之后， 用 douyin_auth.py url + paste 就能拿到真实的 access_token。

这一步能验证的东西不少：后台的 redirect_uri 到底能不能保存、 授权页能不能正常拉起、scope 批了哪些、token 能不能换出来。 这些都是权限之外的不确定性，先排掉。

二、用导出的评论做 M1a

没有接口也能拿到评论：creator.douyin.com → 互动管理 → 评论管理， 逐页复制。这是人工导出，不是自动化，但它能喂给标注工具。 

python label.py
# 来源选「自有账号」，粘贴评论，盲标 100 条，揭晓看一致率

这一步验证的是「判定逻辑对不对」，与接口无关。接口只是取数据的方式， 换成手动导出，判定、生成、闸门、分级放权全都照常跑。

三、把小程序那条路探一次底

一分钟能知道结果，顺序是：

#动作看什么
1open.douyin.com 注册（个人身份）能不能创建「小程序」类型应用
2控制台 → 小程序 → 能力-用户数据能力-抖音账号数据「视频评论数据」的申请按钮是否可点
3点「申请开通」，如实填写用途是否有「该能力已停止申请」的提示
4提交后等 2–3 个工作日批 / 拒 / 要求补充材料

用途别写「营销获客」。写「统一查阅并回复自己账号下的评论、做客服答疑」—— 审核方对「批量触达」这类描述会按营销工具处理，那个方向是收紧的。

如果第 2 步的按钮是灰的

那就意味着官方通道对你当前能创建的应用类型关闭了。此时有两条现实选择： 一是转企业微信，二是用人工导出评论 + 人工发回复的半自动方式。

不建议走浏览器自动化——不是道德判断，是成本判断：它依赖登录态、 随页面改版失效、随时可能触发风控，而你已经明确说过不要风控风险。 那类方案的实际维护成本远高于每天手动粘贴十条。

06 / 这批代码的边界

已经做完的，和还没验证的

能力状态说明
授权链接生成已验证参数完整、redirect_uri 正确编码
code 换 token已验证25 项测试覆盖成功/过期/参数错/网络错
粘贴格式兼容已验证裸码、整条 URL、带引号空格
本地回调服务已验证起服务、收 code、404 路径、超时
令牌落盘与状态已验证重启后能读回，损坏文件不崩
真实换 token未验证需要真实 client_key，我这里没有
后台能否保存未备案域名未验证只能在你的后台点一次
评论权限能不能批未验证只能提交后等审核
小程序接口适配未开发路径、header、item_id 转换都不同，等权限有结果再做

最后一项值得解释：小程序接口和现有代码不是同一套。评论列表路径是 /api/apps/v1/item/list_comment/，token 放在 access-token 请求头， item_id 还得先用 /api/apps/v1/convert_video_id/video_id_to_open_item_id/ 转成 open_item_id。 这些差异写起来不难，但没权限时写了也跑不通，所以等审核结果再动。
