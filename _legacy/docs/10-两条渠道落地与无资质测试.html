Channel Rollout

微信和抖音分别怎么落地，
以及没有资质时能测到什么程度

四个问题的完整答复。核心结论先放在这里：企业微信这条路的门槛比想象中低—— 不需要营业执照也能建应用、也能配回调，只是不能用域名，只能用 IP。 而抖音那条路的门槛比想象中高，卡点不在技术。

2026-11-11 · 226 项测试通过 · 模拟器一次跑通
01 / 企业微信

七步，其中第 3 步有个绕法

先说最容易误解的一件事：企业微信的「自建应用」不需要应用审核。 抖音要提交能力申请等 2–3 个工作日，企业微信建完应用就能收消息。 它慢的地方在开发——要处理 AES 解密和 5 秒响应窗口，那部分代码已经写完了。

注册企业微信，拿到 CorpID

两个入口都能到，但建议用电脑：

入口怎么走适合
电脑（推荐） work.weixin.qq.com → 右上角「企业注册」 注册完顺手就能进管理后台建应用
手机微信 搜「企业微信」公众号 → 底部「联系我们」→「立即注册」 只想先注册，建应用回头去电脑

手机这条路能注册成功，但建应用、配回调都在管理后台， 而手机端的管理后台功能不全。所以手机注册完，还是要用电脑扫码登录后台。

要填的只有四项：企业名称、行业类型、人员规模、管理员姓名 + 手机号。 手机收验证码，再用微信扫码绑定管理员身份。

企业名称可以自拟，用自己的名字加个「工作室」就行，不需要与营业执照一致。 没有营业执照也能填，之后想验证主体再补材料，不影响现在建应用。

耗时 5 分钟 · 需要：手机号 + 一个微信号

建自建应用，拿 AgentId 和 Secret

管理后台 → 应用管理 → 自建 → 创建应用。头像名称随便填，可见范围选自己。

建完进应用详情，抄下 AgentId（纯数字）和 Secret（点"查看"复制）。改完 Secret 旧的立刻失效，别反复点。

耗时 3 分钟 · 产出：AgentId、Secret

配回调地址 —— 没有营业执照时用 IP，不要用域名

应用详情 → 接收消息 → 设置 API 接收。要填三样：URL、Token、EncodingAESKey。

这是全流程唯一有坑的一步。 企业微信要求回调域名必须与企业认证主体一致（备案主体相同）。 没营业执照 → 没认证 → 域名配不上。

官方给未认证企业的做法是：直接填 IP 形式的回调 URL—— http://1.2.3.4:8780/wecom/callback。 然后用同一个 IP 去配「企业可信 IP」。这条路能走通，只是要求你有一台公网服务器。

本机没有公网 IP 时，用内网穿透（cpolar、natapp、frp 都行）拿一个临时公网地址， 但要注意穿透服务给的通常也是域名，未必过得了主体校验。先用 IP 试。

耗时 10 分钟 · 需要：一台有公网 IP 的机器

填 wecom.json，起服务

复制 wecom.example.json 成 wecom.json，把四个值填进去。

{
  "corp_id": "ww1a2b3c4d5e6f7g8h",
  "corp_secret": "应用详情页那个 Secret",
  "agent_id": "1000002",
  "token": "自己定，会用于验签",
  "encoding_aes_key": "43 位，点随机获取",
  "port": 8780
}

python wecom_server.py --config wecom.json --dry　先只收不回。

耗时 2 分钟 · wecom.json 已加进 .gitignore

回后台点「保存」，看它是不是绿的

企业微信会立刻发一个加密的 echostr 到你的地址，服务端解密后原样返回， 就算验证通过。返回慢一点、多一个空格、多一个引号，都会失败。

这一步在本地就能预演——模拟器里 verify_url() 做的就是这件事，返回 通过 说明协议实现没问题。

耗时 1 分钟 · 失败原因 90% 是服务没起来或端口没通

用两个号对聊，观察一周

自建应用只能发给企业成员。所以最省事的验证方式是：通讯录里加两个号， 一个当客服、一个当顾客，真人演一遍售前咨询。

外部客户要走「微信客服」，那是另一套接口（kf/sync_msg），不在这一版里。

耗时 30 分钟 · 建议 --dry 跑满一周再放开

换掉人设语料，重跑一次校准

评论语料在聊天里会说出很怪的话。实测：「这个桌子多少钱」在评论语料下答 「价格我私信你说，评论区不太方便聊这个」——用户已经在私聊里了。

所以先用 personas/wecom_chat.json 那份聊天语料，然后按真实对话继续补。

耗时 持续 · 这是唯一没有终点的步骤
一个会真正亏钱的地方

上面那段输出里，「这个桌子多少钱」答出了 「原木色 399」。 这个 399 是写在 few_shot 里的，不是从 knowledge 读的。

所以改价格必须同时改语料。忘了改，系统会理直气壮地报一个旧价， 而且每条都报，比人工报错还稳定。

上线前的必查项：把 persona.json 里所有含数字的语料搜一遍， 价格、时效、尺寸都在里面。这类信息放在 knowledge 里更安全， 但它只保证"答得上"，不保证"说得像人"——两个都要。

如果连公网 IP 都没有

那就只能本地跑。模拟器可以验证全部代码逻辑，但收不到真实消息， 也做不了 M2 的采纳率测试——采纳率必须是你看着真实消息做的判断。

最便宜的解法是一台 2 核 2G 的云服务器，几十块一个月，够跑这个服务。

02 / 抖音

五步，卡在第二步

抖音这边代码已经写完了，缺的是账号和权限。剩下的操作是纯后台流程，不涉及开发。

注册开放平台，创建应用

访问 open.douyin.com，用抖音号登录 → 控制台 → 创建应用。

应用类型决定后面能做什么。个人主体通常能创建移动应用和网站应用； 网站应用要求域名已备案，移动应用要求包名和签名。

耗时 10 分钟 · 个人可注册，无需企业

申请「视频评论管理」能力

应用详情 → 能力管理 → 找到「互动管理 / 视频评论」→ 申请。

官方能力页原话是「暂无准入条件，任一应用均可申请」，审核 2–3 个工作日。 但社区里个人主体被拒的反馈不少，实际卡点可能是"能创建什么类型的应用"而不是能力本身。

申请理由别写"营销获客"。写「统一查阅并回复自己账号下的评论、做客服答疑」。审核方对"批量触达"这类描述会直接按营销工具处理，那个能力包是收紧的。

耗时 2–3 工作日 · 通过率不确定，要留退路

配置 OAuth 回调，走一次授权

拿到 client_key / client_secret 后，拼授权链接让账号主人点一次， 回调里拿到 code，换 access_token + refresh_token + open_id。

回调地址同样要求是备案域名。这是抖音这边真正的门槛——它没法用 IP 绕过。

耗时 半天 · 需要：已备案域名

填 token.json，跑一次真实拉取

python douyin.py 目前跑的是假数据。换成默认 transport 就是真接口，业务代码一行不改。

第一次只拉一页（--pages 1），确认字段能对上，再放开。

耗时 20 分钟 · 令牌 15 天过期，已实现自动续期

挂 scheduler，观察七天

python scheduler.py 定时轮询 + 令牌预警 + 队列积压告警。

七天里要满足三条：不漏（该拉到的都拉到）、不重（同一评论不回两遍）、不自回自答（不把自己的回复当新评论）。

耗时 7 天观察 · 三条都过才算接入成功
卡点在哪

抖音卡的不是代码，是已备案域名。企业微信可以退到 IP，抖音不能。 域名备案要 3–20 个工作日，且需要主体资格。

这一条如果过不去，抖音这条路在当前阶段就跑不通真实链路，只能停在本地演示。

03 / 无资质测试

三档，能测到的深度完全不同

这轮补了第一档：一个不需要任何凭据、但走真实 HTTP 和真实 AES 的模拟器。 它不是打桩——它冒充平台，把消息真的加密、真的签名、真的 POST 过来。

档位怎么跑能验证什么验证不了什么
回放
demo_run.py		 读评论快照，跑判定与生成，结果投到本地文件或群机器人 判定逻辑、生成质量、拦截规则 协议、网络、平台行为
模拟器
wecom_sim.py		 本地起两个服务：一个冒充平台，一个跑真实回调 加解密、签名、URL 验证、去重、5 秒窗口、发送失败处理 真实用户语态、真实频率
真机
wecom_server.py		 公网 IP + 真实凭据，两个号对聊 全部，包括最关键的采纳率 —

假平台实际收到 7 条消息

  ✓ 回调地址验证：加密 echostr 原样解回
  ✓ 消息能到达：推送 10 条，入队 10 条
  ✓ 确实发出去了：假平台收到 7 条，而非只记在本地
  ✓ 边界确实拦住了：拦截 2 条
  ✓ 令牌只取一次：缓存生效
  ✓ 重复推送去重：同一 MsgId 推 3 次，入队 1 条

结论：通过 —— 全链路可用，差的只有真实凭据

这六项检查里，「确实发出去了」和「重复推送去重」是新增的。 前者保证不是"记在本地就算发过"，后者对应平台的真实行为—— 5 秒内收不到响应会重试三次，MsgId 不变，不去重就是同一句话回三遍。

为什么不用打桩

替换 transport 能测业务逻辑，但测不到 URL 编码、CDATA、Content-Type、端口绑定， 而这些恰恰是真实部署第一天会出错的地方。所以模拟器连 HTTP 层一起走。

想看它自己动起来：wecom_live.py

上面那个模拟器是「跑一遍就退出」，用来证明链路通。但它有个缺点： 看不出这是自动的——一次性批处理，和人工逐条处理在观感上没区别。

所以另做了一个常驻的聊天窗口：

$ python wecom_live.py
  人设      小陆
  模式      自动发送
  回调验证  通过（协议层：加密 echostr 原样解回）
  打开      http://127.0.0.1:8790

  在浏览器里打一句话，1 秒多会自动回复。

打开就是一个企业微信风格的聊天界面。打一句话，几百毫秒后自动回复， 气泡下面标着这次判定的全部依据：

你说结局耗时气泡下面显示什么
在吗自动回复745ms私聊一对一，边界没命中，闸门放行
这个桌子多少钱自动回复603ms原木色 399，黑色下周到
能便宜点吗拦截482ms命中人设边界：便宜点
嗯不回复396ms判定不回复：纯语气词，无信息量

第三行是这套东西最有说服力的地方：它不会回你。 界面上出现的是一条居中的系统提示「拦截 · 命中人设边界：便宜点」， 而不是一个气泡。会拒绝，才像有边界的东西。

它真的在跑协议

你在输入框打的字，走的路径是：AES-256-CBC 加密 → SHA1 签名 → HTTP POST 到本地回调 → 验签解密 → 判定 → 生成 → 闸门 → 调 message/send → 假平台收下 → 界面显示。

所以这里面的延迟是真实处理时间，不是写死的动画。 换成人话解释：这套代码换成真凭据、把回调地址指向公网 IP，就是生产环境。

判定层：可迁移 8/10

  • 意图词表跨场合通用——"多少钱"在评论和私聊里都是购买意图
  • 分歧的 2 条都是"语料没覆盖"，不是逻辑错
  • 所以用评论数据校准判定，是可行的

  • 评论语料答不出"开票""什么时候发"这类客服问题
  • 更糟的是答错场合：「价格我私信你说」——用户已经在私聊里了
  • 所以采纳率必须用目标场合的真实数据
结论
M1 拆成两个指标：M1a 判定一致率可以用视频评论做， M1b 草稿采纳率不行，必须用聊天场景的真实记录。 所以现在用评论数据开始做 M1，方向是对的——只是别把它当成"聊天也准备好了"。

具体怎么操作

判定那部分现在就能做，用的是已有的标注工具，把来源选成 comment： 

# 1. 起标注工具（8771）
python label.py

# 2. 粘贴评论，来源选「自有账号」，盲标 100 条
# 3. 揭晓，看一致率与两类分歧

聊天那部分要等企业微信跑通，因为它需要真实对话。在那之前， wecom_sim.py 的 10 条场景只能验证链路通不通，不能当校准数据—— 那 10 条是我写的，不是用户说的。

一个必须说清楚的区别

「评论数据能校准判定」不等于「抖音做完就等于微信做好了」。 判定逻辑复用度 80%，但这 80% 里不含任何一句人话。 剩下的 20% 判定分歧和全部的话术，都得在目标场合重新来一遍。

05 / 顺序

先做企业微信，理由不是它更快

两边都能做，但如果只能先做一边，选企业微信。理由和速度无关。

判断维度企业微信抖音
应用审核不需要2–3 工作日
域名要求可用 IP 绕过必须已备案
代码状态已完成并验证已完成并验证
能拿到真实对话能（两个号对聊）要等权限
适用场景一对一客服、售前咨询公开评论区
公开风险低（一对一，说错只有一个人看见）高（公开，说错所有人看见）

决定性的那一行是「能拿到真实对话」。 项目现在的瓶颈不是功能，是 M1b 采纳率——而这个数字只能靠真实对话积累。 企业微信是唯一「不等审核 + 官方支持 + 当天能拿数据」的渠道。

抖音那边同步提交申请就行。权限下来后只换适配器，判定、生成、闸门、持久化一行不改—— 这部分在 226 项测试里已经锁住了。

如果两边资质都没有

那就把顺序倒过来：先用评论数据把 M1a 判定一致率做到 80%， 同时用模拟器保证企业微信那份代码不会烂。 等哪天拿到主体资格，接上去就能跑，不用重写。

这不算"假装在做"，因为判定逻辑确实是通用的—— 只是要清楚，草稿质量那部分还没被验证过。

数据来源：本轮实跑。模拟器输出、跨场合对比、测试数量均为实测值。

企业微信回调地址规则以管理后台实际显示为准——未认证主体能否配 IP 形式回调，

官方社区答复为「可以」，但不同账号可能有差异，以你点「保存」时是否通过为准。
