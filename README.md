# AutoReply

Android **半自动**回复工具：读消息 → 生成草稿 → 填进输入框 → **发送永远由人点**。

自用工具，不是对外服务。与同目录下的求职自动化项目没有代码、数据或账号关联。

> 最后更新：2026-11-22 ｜ 当前版本：v0.1.1

---

## 这是什么 / 不是什么

| 会做 | 不会做 |
|---|---|
| 对方发来新消息时，自动读出对话 | **不会替你发送** —— 代码里没有任何路径能触发发送按钮，输入法面板上也没有发送键 |
| 用你配的模型 + 人设生成一句回复 | 不会主动开口（只在对方先说话时才动） |
| 把草稿填进输入框，光标停在那儿 | 不会自动点开会话（你进哪个会话，它就在哪个会话里干活） |
| 按真人的节奏拆成 1~3 条、分开填 | 不上传任何东西（人设、词表、Key 都在本机） |

**核心约束：`ReplySink` 接口里根本没有 `send()`。** 这不是"还没做"，是设计上不做 ——
发送是这条链上唯一有对外后果、且不可撤销的动作，必须留下人这一下。

## 当前进度

链路已闭环，但只在**第一道门**上有真实数据。诚实地说：

```
界面出现新消息 → 五层判定 → 生成 → 填入草稿 → 你点发送 → 系统确认已发送 → 等下一条
       ✅            ✅         ✅        ✅          👤            ✅
```

| 已完成 | 说明 |
|---|---|
| 读屏与节点抓取 | 多平台选择器配置化，换平台只加 `profiles.json` 一段 |
| 五层判定链 | 平台闸门 / 该不该回 / 精力 / 生成 / 话术风险，每层结论显示在界面上 |
| 三条写入通道 | 无障碍 → 输入法 → 剪贴板兜底，后两条都会回读校验 |
| 发送确认 | 靠消息列表里出现"我发的那条"判断，配额只计真实发送 |
| 去重 / 限流 / 熔断 / 精力 | 拟人节奏 + 平台风险两层分开管 |
| 纸感 UI 三页 | 首页 / 设置 / 话术管理，共用一套 token，零第三方依赖 |
| 开场白钩子库 | 20 条内置模板，支持 `{昵称}` `{原话}` `{时段}` 槽位与游标轮换 |
| 说话风格 | 自然 / 温柔 / 俏皮 / 高冷 / 直接，输入法面板第二页随手切；只改语气，不碰长度与底线 |
| 输入法面板 | 两页可滑动：回复动作（生成 / 换一句 / 开场白 / 复制）与模式风格；**没有发送键** |
| 演练模式 | 不联网、不花 Key，按话术样例拼回复，能验证续聊链路 |

| 还没做（按优先级） | 为什么重要 |
|---|---|
| **回复率埋点** | 现在只有"感觉回复少"，没有数字。没有它，话术好坏无法归因 |
| 人群筛选（在线 / 资料完整度） | 从"群发 100 条"到"精选 10 条"，这一步的杠杆比改话术大一个量级 |
| 发送时段控制 | 这类平台活跃峰值在 20:00–23:30，半夜发基本埋在列表里 |
| 他趣读消息 | 整棵无障碍树被 App 主动关闭，只能走通知监听 |
| 抖音适配 | 选择器已写好，未真机验证 |

**当前瓶颈不在代码**：陌生号第一条消息的回复率，主要由资料页（头像真实性、照片、签名）
和目标人群决定，话术只占小头。这一点写在 README 里，是为了避免下一个人继续在话术上死磕。

## 一条消息怎么走完

```
通知 / 界面变化
   ↓
① 平台闸门      每小时上限、连续上限、冷却、熔断（平台报警后 30 分钟）
   ↓
② 该不该回      必要性判定：纯招呼 / 已聊过 / 多久前说过话 / 是否在约
   ↓
③ 精力          真人会累、会拖；手动点击时这一层让路
   ↓
④ 生成          固定开场白（钩子库）→ 否则调模型 / 演练假模型
   ↓
⑤ 话术风险      价格、承诺、赔付类不自动填，只提示
   ↓
填入草稿（断句 → 1~3 条，一条一条填，每条都由你点发送）
```

## 用户可见的能力

### 开场白钩子库

对方先发招呼时用它开口，不调模型、不花 token。一行一条，**一条就是一条要发出去的消息**。

```
这么晚了还没睡，在刷什么
{昵称}，这名字谁给你起的
{原话}，就这么一句啊
我这人睡得晚，{时段}才有精神
```

- 槽位填不上就**跳过那一条**，绝不把 `{昵称}` 这种字面量发出去（纯数字系统号也算填不上）
- 按游标轮换，第 1 个会话用第 1 条，走到底绕回来
- 库内句子不再二次断句：按逗号拆会把问句甩到第二条，只发第一条就丢了钩子

### 演练模式

不联网、不花一分钱，用你自己配的问答样例拼回复。用来验证"管道通不通"和"续聊接不接得上"。

场景池分开：被约时有专门的软钉子（`DEFLECT`），挡完还会抛一个新话题（`TOPICS`）——
只挡不抛，对话就死在"我不太敢"这里，等于没接。

> 演练模式测的是**流程**，不是文采。真实效果要接模型 Key。

### 平台支持

| 平台 | 读消息 | 填草稿 | 备注 |
|---|---|---|---|
| moyi / 心遇 | ✅ | ✅ | 结构最规范，输入框标准 |
| 同城夜聊 | ✅ | ✅ | 输入框对无障碍不可见，需启用「简输入」 |
| 他趣 | ❌ | ✅ | 整棵树被 App 关闭无障碍，读不到消息 |
| 抖音 | ⚠️ 未验证 | ⚠️ 未验证 | 选择器已配好，等实测 |

### 护栏

| 层 | 管什么 | 默认 |
|---|---|---|
| 每小时上限 | 真发出去几条 | 15 |
| 连续上限 | 连续几条后歇一会儿 | 8 |
| 长冷却 | 歇多久 | 5 分钟 |
| 熔断 | 平台报警后强制停 | 30 分钟起（带 0.85~1.4 倍随机抖动，且落盘，重启不能绕过） |

## 本地自检（push 前必跑）

**本机不装 JDK / Android SDK，编译不了** —— 所以每一步能本地查的都查掉，
不然一轮 CI 白跑几分钟。

```
bash tools/precheck.sh
```

| # | 防什么 | 为什么值得 |
|---|---|---|
| 1 | 用了 `R.` 却没 `import com.autoreply.app.R` | 必现失败 |
| 2 | layout 引用的 string / color 不存在 | 必现失败 |
| 3 | `findViewById` 的 id 没在布局里声明 | 必现失败 |
| 4 | Manifest 声明的类不存在 | 必现失败 |
| 5 | `assets/*.json` 非法 | 运行时才崩 |
| 6 | 用了别的包的类但没 import | 最常见的一类 |
| 7 | 乱码字符 / 字符串没闭合 | 报错位置对不上真实原因 |
| 8 | `addView(xxx(...))` 里的 `xxx` 不存在 | 改函数名漏改调用处 |

纯逻辑（断句、轮换、槽位填充、词表判定）另用 Python 复刻同一份算法验算，
**词表直接从 `.kt` 源码里 regex 读，不手抄**：

```
tools/verify_splitter.py        断句不丢字、不多标点
tools/verify_greeting_hooks.py  钩子库轮换与槽位跳过
tools/verify_drill_pools.py     系统提示过滤 / 邀约判定 / 连点取词多样性
```

## 构建与发版

```
git push         → Actions 出 release APK，在 artifacts 里下载
git tag v0.1.2   → 额外创建 Release 并附上 APK 和 RELEASE_NOTES.md
```

本地有环境时：`gradle assembleRelease`（需要 Gradle 8.2 + JDK 17 + SDK 34）。

出 release 而不是 debug：debug 包带 `android:debuggable`，别人装上等于给了一个可挂调试器的进程。
混淆是关的（`isMinifyEnabled = false`），崩溃栈依然可读。

### 签名

仓库 Secrets 里配 `KEYSTORE_B64`（.p12 的 base64）和 `KEYSTORE_PASS`。
未配置时 CI 会现场生成临时密钥 —— 能出包，但每次签名不同，**无法覆盖安装**。
每次构建会把签名指纹写进 Actions 的 Step Summary，验证覆盖安装时对比它。

### 零第三方依赖

不引 androidx / Material / Compose / OkHttp / Gson。HTTP、JSON、Trie 全用系统 API 手写。

理由：每多一个依赖，CI 首次构建就多一处会坏的地方；而本项目需要的这几样，
手写几百行就能覆盖。这条约束也决定了 UI 只能用系统主题 + `shape` drawable + 系统字体来做质感
（见下面的决策记录）。

## 分发前须知（APK 里到底带了什么）

别人装到的**不是空白版**。当前 APK 里打包了这些东西：

| 位置 | 内容 | 装完的状态 |
|---|---|---|
| `assets/persona.json` | 通用人设 + **28 条问答样例** + 10 条行为准则 + 4 条知识 + 14 条边界 + 18 个禁忌词 | **原样带过去，开箱即用** |
| `core/llm/GreetingHooks.kt` | 20 条开场白钩子模板 | 代码里有，但**默认不启用** —— 要在设置页点「载入内置 20 条」 |
| `AppConfig.greetingLines` | 默认空 | 空 → 交给模型写开场 |
| `AppConfig.llmBaseUrl` / `llmModel` | 默认 `api.deepseek.com/v1` / `deepseek-chat` | 地址默认有，**API Key 必须自己填** |
| `AppConfig.targetPackages` | 默认空 | 不筛选，任何非本 App 界面都抓 |
| API Key / 人设覆盖 / 禁忌词 | —— | **不包含，永远不进包** |

一句话：**内置了「人设与话术样例」，没有内置「你的 Key」**。

### 要发给别人，先决定样例怎么办

`assets/persona.json` 里的 28 条问答样例是话术资产 —— 那是"这个号怎么说话"的底子，
发出去等于把话术一起发了。二选一：

1. **改包**：把 `few_shot` 换成通用样例（或只留几条占位），重新打包
2. **不改包**：让对方在自己的「设置 → 人设 JSON」里粘贴自己的版本（优先级高于内置）

> 同一套话术在同一个平台上跑多个号，是最容易被关联识别的一种。这是现实理由。

## 已知限制

- 界面结构变化会导致读取失败，需要重新抓节点树更新 `profiles.json`
- 需要 Android 8.0 以上
- 部分机型要手动允许自启动，否则服务会被系统回收
- 交友类平台大量新会话第一句都是「你好」，去重按「昵称 + 消息内容」判定，
  昵称读不到时会退回纯文本（有误判风险）
- 平台营销提示与真人消息混在同一个列表里，靠特征短语 + 长度门槛过滤，
  文案大改时可能漏判

## 免责

自动化操作可能违反目标平台的服务条款，账号可能被限制或封禁。自行判断是否使用。

本项目不含任何自动发送能力，也不提供任何绕过平台风控的手段 ——
它的定位是"替你把草稿打好"，不是"替你聊天"。
