## 短语插入会接在用户已打的字后面（真机：11先聊两句吧…）

现象：输入框里已有「11」（用户自己打的），点常用短语 → 变成「11先聊两句吧，我这边不急」。

根因：`insertPhrase` 走的是 `commit(text)`，而 `commit` 里清场只调用 `clearOwnDraft()` ——
它**只删我们上一次写的那段**（还要光标前内容以 `lastCommitted` 结尾）。
用户自己打的字不属于我们，所以一个字都不动，`commitText` 就在光标处插进去。

这是当初"绝不覆盖用户输入"这条原则的副作用：自动填入需要它，但**用户亲手点按钮**时
意图恰恰相反 —— 我要发的就是这句。

## 修法：分成两条路，别混用

- 新增 `AutoReplyImeService.replaceAll(text)`：读 before/after → `setSelection(0, total)` →
  `commitText`。覆盖前如果框里的内容**不是我们写的**，先 `copyDraft(原内容)` 备份，
  并用 `lastFillBackedUp` 让状态行说清「已替换（原内容在剪贴板）」。
- 改动点：`insertPhrase`（常用短语）、`commitGreeting`（用开场白）、语音 `onResults`（说一句）。
- **不动**：`commit()` 本身（TextWriter 自动填入仍走它）、「粘贴」按钮（等同真键盘粘贴，
  用户可能真想接在后面；旁边有「清空」）。

## 判断依据（以后再遇到类似问题）

「谁点的」决定清场强度：
- 用户亲手点的填充动作 → 整框替换（并备份）
- 程序自动填入 → 只清我们自己的草稿，绝不碰用户的字

`setSelection` 在个别 InputConnection 上会抛，已 runCatching 兜底成
`deleteSurroundingText(before, after)`。

## 发完招呼又追一句：把"最后一条对方消息"当成"最新消息"

症状：发出开场白后，程序又生成了一句，屏幕上看着像"在回我自己"。

根因（两处，同一类错误）：
- `CaptureService.maybeAutoReplyOnChange()`：只取 `messages.lastOrNull { it.fromOther }`，
  **不检查它是不是最后一条消息**。我发完招呼后，对方那句「你好」仍是"最后一条对方消息"，
  于是被拿去生成 —— 重复回同一条旧招呼。
- `ReplyFlow.decide()`：同样只取最后一条对方消息，没有"对方还没回"这道判断。
- 面板「用开场白」这条路径**不经过 ReplyDedup**，所以没有任何机制拦住这次重复。

修法（三道门，按成本从低到高）：
1. `CaptureService`：`if (messages.lastOrNull()?.fromOther != true) return` ——
   自动触发先拦，**连模型都不调**（省 token）。
2. `ReplyFlow`：同一道门 `if (!manual && turns.lastOrNull()?.fromOther != true)`
   → `Silent("对方还没回，先不追")`，覆盖通知驱动等其他入口。
3. 手动生成（用户明确要求）不拦，但提示词结尾改成
   "最后一句是我说的，对方还没回。不要回复自己这句话；如果必须写，就接着往下说一句。"
   —— 否则 `请回最后这一条。` 会让模型去回我方那句。

判据采用最硬的一条：**最新一条不是我方的，才叫"对方说了新话"**。
不要把 `selfSaidAgoSeconds` 那套分数拿来当门 —— 它只扣分，手动/连点还会让路。

注意：连点（batch）走 `manual = true`，所以不受第 2 道门限制；
它只在"下一个未读"里推进，那边最新一条本来就是对方的，风险低。

## 面板第三页「话题」（找话题）

用户要「展开下拉框里再加一个找话题的框，按不同类型分类」。实现为 SlidePager 的第 3 页，
页签从「回复 / 风格」变「回复 / 风格 / 话题」，三格均分。

- 数据：`core/llm/TopicBank`（硬编码，5 类 × 5 句 = 25 句）。
  分类：日常 / 工作 / 兴趣 / 感情 / 见面。
  **刻意不做成配置**：通用社交常识，做成配置的结果是没人填、功能等于不存在；
  要个性化有「常用短语」那一栏。
- 句子标准：一句一个具体问题、不问隐私（收入/体重/家庭矛盾）、对方答完能自然接。
- 交互：上方类别 chips（复用 `chip()`，选中态走全局 restyle），下方整宽行列表，
  点一行 → `insertPhrase()` → `replaceAll`（整框替换 + 覆盖前备份），和常用短语同一套语义。
- 高度：列表放 `ScrollView` 固定 `dp(118)`；这一页行数不固定，跟着内容变会让面板切页时上下跳。
- `cfg.imePage` 的 `coerceIn` 从 (0,1) 改成 (0,2)，否则第 3 页永远存不住。
- `updateHint()` 加第 3 页文案："点一句就填进输入框（会替换掉框里现有的）"。

踩坑记录：precheck 第 6 步（漏 import）抓到 `TopicBank` 没 import —— 新类被引用时
必须同时加 import，本机不编译，只能靠这一步兜。

## CI 报 Unresolved reference: ScrollView（平台类漏 import）

`AutoReplyImeService.kt:440` —— 话题页里写了 `ScrollView(this@AutoReplyImeService)`，
文件没有 `import android.widget.ScrollView`。

**为什么 precheck 没拦住**：第 6 步（check_imports.py）只查**项目内**的类
（`com.autoreply.*`），平台类漏 import 它看不见；第 1 步只管 `R.`。

补了 `tools/check_android_imports.py` → precheck **第 12 步**：
- 先剥注释、剥字符串字面量（保留换行，行号才对得上）；
- 对一份人工维护的平台类清单（View/TextView/ScrollView/AlertDialog/ClipboardManager…），
  找**不带前缀**的使用（`(?<![\w.])Name\b`，排除 `android.widget.ScrollView` 这种全限定写法）；
- 文件里没对应 import、也没自己声明同名类 → 报 `文件:行 用了 X 但没有 import`。
- 用"删掉 import 的副本"验证过：能精确报出 `T.kt:440 用了 ScrollView 但没有 import`，
  和 CI 那条一致。

**维护提醒**：清单在脚本顶部 `PLATFORM_CLASSES`，加新 UI 控件时把类名补进去，否则会漏报
（宁可漏报也不误报，这条是有意的）。

## 两个反馈：抽到"淄博"其实是我方说的 + 试填里看不到「关于对方」

### ① 方向判错被抽成事实

`NodeQuery.readMessages` 的方向判定：id 前缀（left_/right_）优先，否则 `r.left < rootWidth/3`。
同城平台/iOS 风格布局上，我方气泡 left 也可能 < 1/3 → 我方那句「我在淄博做美容」
被当成对方的。而我的 persona 身份正好是"在淄博做美容"，所以一抽就中。

修法（不靠猜方向，靠交叉验证）：
- `FactExtractor.extract(turns, selfIdentity)`：抽到的 **city/job** 如果出现在人设 identity 里
  → **置信度降到 0.5**（低于 0.7 → 不进提示词，但留在库里标"不确定"）。
- 为什么是降级不是丢弃：同城交友平台上"对方也在淄博"一点都不稀奇，直接丢会误杀真事实。
- `observe(..., selfIdentity=)`；`ReplyRunner` / `MainActivity` 用
  `PersonaLoader.resolve(...).persona.identity` 传进来。

### ② 事实带来源（DB v2）

`sessions_memory.db` 从 v1 升 v2：`ALTER TABLE facts ADD COLUMN src TEXT NOT NULL DEFAULT ''`。
每条事实存"抽到它的那句原文"（截 30 字），`MemoryActivity` 每行下面用 10sp 灰字显示
「来源：…」。抽错时这一行就是唯一能解释"为什么记成这样"的东西。
**升级只 ALTER 不重建** —— 重建等于清空用户已有的记忆。

### ③ 「关于对方」在试填里看不到

不是没注入，是被截断了：试填只显示提示词**前 1200 字**，而 system（人设/样例/准则）
本来就一千多字，user 段永远在窗口外。
改：`MainActivity` 判定链下面单独一行 `关于对方（N 条）：…`，三种状态说清楚：
`跳过（读不到昵称）` / `无（还没记到事实）` / 具体列表。
`ReplyRunner` 同时 `logAuto("记忆：带上 N 条关于对方")`。

`tools/verify_fact_extractor.py` 已同步（逐句抽取 + 来源 + 降置信三种情况），
precheck 第 11 步仍是绿的。
