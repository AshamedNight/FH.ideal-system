## 「同一句连点生成结果相同」+ 输入框叠加（commit d1d6a7e）

用户截图：输入框是 **「怎么说怎么说怎么说」** —— 三遍叠在一起，状态行还停在上一轮。
两个独立问题叠在一起：

### ① 输入框叠加（bug 级）
`InputConnection.commitText` 是**在光标处插入**，不是覆盖。
`TextWriter.write(replaceExisting=false)` → `ime.commit(text, replaceFirst=false)`，
所以连点三次就是三份追加。

修法：`AutoReplyImeService` 记住 `lastCommitted`，写新草稿前调 `clearOwnDraft(ic)`：
只用 `getTextBeforeCursor` 读回，**只有当框里内容以 lastCommitted 结尾时**才 `deleteSurroundingText`。
- 用户点发送后 App 清空 → `verifyWritten` 把 lastCommitted 置 null
- 用户自己接着打字 → 不满足 endsWith → 一个字不动
满足"连点不叠加"的同时守住"绝不覆盖用户输入"这条底线。

### ② 同一条消息重复生成结果相同
`DrillReplier.reply(persona, last.text, turns.count { it.fromOther })` ——
round 只由"对方说过几句"决定，**同一条消息重复生成时它根本不变**，
`pick()` 的索引也就不变 → 三次都给同一条。

修法：`AppConfig.drillNudge`（每生成一次 +1，持久化），
`pick(pool, seed, round, nudge)` = `(hash + round*7 + nudge*13) % size`；
样例轮换 `sameQ[floorMod(round + nudge, size)]` 也掺进去。
真实模型不需要（每次本来就不同），只在演练分支自增。

### 验算
`tools/verify_drill_pools.py` 加了【3】连点场景：
同一条「你约？一小时两张」+ 同一 round，nudge 0..5 → 6 条全不同；
邀约场景 nudge 0..3 → 4 条全不同。

## 二次招呼重复发开场白（commit 68b2619）

**现象**：聊到一半，对方（或平台「缘分小助手」）又来一句招呼，输入框里又冒出
「突然有点想认识你」。

**根因**（演练模式）：`DrillReplier` 只拿最后一句话查 `few_shot`，
而 `assets/persona.json` 里 `q="你好"` 配了两条**开场型**答案：
「突然有点想认识你」和「在吗？」。已聊过时查表照样命中 → 又把开场白说一遍。
`buildUser` 里那段"二次招呼别自我介绍"的提示只对真模型有效，假模型根本不看提示词。

**修法**：
- `DrillReplier.reply()` 新增 `alreadyTalking` / `peerJustGreeted` 两个参数，
  由 `ReplyEngine` 把算好的 `iSaidAlready` / `peerOpenedWithGreeting` 传进去
  （**不在 DrillReplier 里重写一份 isJustGreeting**，两份判定早晚走偏）
- 一次都没聊过 → 正常查表；已聊过 + 对方只是招呼 → 走 `REJOIN` 池（在呢/刚看到/刚忙完）
- `NodeQuery` 新增 `SYSTEM_SENDERS`（缘分小助手 / 缘分天使 / 丘比特 / 系统消息 / 平台助手），
  **不看长度**直接丢 —— 这类消息以真人气泡形式出现，被当成"对方第一次打招呼"时
  会触发反问开场白，而对方其实什么都没说

**验算**：`verify_drill_pools.py` 加【1b】，连取 4 次都不落在那两条开场样例上。

## 「手动生成和自动都失效」（commit 77d32f7）

用户截图判定链是关键证据：
```
① 平台闸门：通过（本小时 0/600）
② 该不该回：想回但先等（私聊 +0.48；单字 -0.20；总分 0.28）  等 4 分钟再回
```

### ① 第②层没给手动让路（核心 bug）
`respectEnergy` / `respectCooldown` 只放开第①层和第③层，**第②层的
`NecessityJudge.Action.WAIT` 直接 `return Outcome.Wait(...)`** ——
所以手动点「生成并填入」也纹丝不动。界面上看就是"程序坏了"。

修法：`ReplyFlow.decide()` 新增 `manual` 参数，WAIT 分支在 manual 时只写 trace 放行。
边界：**内容类判断不让路**（SILENT / 话术风险仍拦）—— 那是"说错代价大"，不是"时机不对"。
调用处：`ReplyRunner` 传 `manual || config.drillMode`，`MainActivity` 传 `true`。

### ② 单字统一 -0.20 罚错了对象
「在」是应答，不是敷衍。而真敷衍（嗯/哦/好/行/哈哈/草）在 `FILLER` 正则那步
**早就短路成沉默了** —— 能走到扣分逻辑的单字基本只剩「在/是/对」。
→ 删掉整段单字惩罚。改完「在」= 0.48 ≥ 阈值 0.45 → REPLY。

### ③ 库为空时演练退去 few_shot 拿开场白
截图里设置页开场白库是**空的**，于是走演练 → 查 `q=你好` →
「突然有点想认识你」。用户清空库的本意是"别再发那句"，反被样例接回来。

修法：演练模式 + 库为空 + 开场轮 → 用 `GreetingHooks.DEFAULT` 兜底（抽出 `pickGreeting()` 复用轮换）。
库里有内容时仍以用户的库为准；非演练模式库为空仍交给模型。

**留给用户验的判据**：改后同样的「在」应该显示
`② 该不该回：该回（0.48…）` 而不是「想回但先等」。

## 风控评估：输入法面板化（分析，未实施）

用户问"面板化对风控是提升还是降低"。

**结论：面板本身中性。** 平台只能观测自己 App 内的行为（消息内容 / 时机 / 频率 / 会话数），
输入法是另一个 App 的 UI，平台读不到"在面板上点了几次"。

| 观测面 | 变化 |
|---|---|
| 消息内容 | 不变 |
| 发送频率 | **可能上升**（生成不用切 App，摩擦消失）← 唯一实质风险 |
| 写入通道 commitText | 不变 |
| 前后台切换次数 | **下降**（略降风险：同账号在聊天页反复失焦是弱信号） |

护栏（每小时 15 / 连续 8 / 熔断 30min）都在 ReplyFlow 里，面板只是换个按钮位置，绕不过去。

**三条实施约束**：
1. 跨会话批量动作（连点下一个 / 切换会话）**不要上面板** —— 一键跨多会话是"脚本"的典型形状
2. 发送按钮别配"发完自动生成下一条"，否则节奏变成固定间隔
3. 输入法改名（见下）

### ⚠️ 原本就漏掉的暴露点：输入法的名字

`AndroidManifest.xml` 里 `ime_label = "AutoReply 输入"`、`ime_subtype_label = "AutoReply 写入通道"`。
**任何 App 都能用 `InputMethodManager.getEnabledInputMethodList()`（无需任何权限）**
枚举设备上启用的输入法并 `InputMethodInfo.loadLabel()` 读到这个名字。

也就是说交友 App 完全有能力检测"用户默认输入法叫 AutoReply"。
这跟面板做多大无关，但比面板的风险更实在 —— 建议改成中性名（如「简输入」）。

**AndroidManifest 里没有 `QUERY_ALL_PACKAGES` 之类限制，这条纯靠改名缓解。**

## 输入法面板第一步（commit c2f3fe2）

`AutoReplyImeService.onCreateInputView()` 从"一行横条"改成可展开面板。

- **折叠态**（默认）：一行，左侧 "AutoReply 输入" + 「展开」「键盘」链接。高度跟原来一致，不挡聊天。
  状态存 `AppConfig.imePanelExpanded`（默认 false）。
- **展开态**（约 216dp）：
  - 把手行：状态 + 收起 + 键盘
  - 草稿预览行：`getTextBeforeCursor(80)` 读回，白底
  - 左网格：生成下一条 / 换一句；用开场白 / 复制草稿；通栏「打开 App · 看判定链」
  - 右列 52dp：粘贴 / ⌫ / 清空（米底 `bg_ime_key`）
  - 底部一行小字「发送仍然由你点」
- 动作复用现有实现，不另写：`generate()` → `ReplyRunner.runOnce(manual = true)`；
  `换一句` 先 `clearOwnDraft()`（避免叠成「怎么说怎么说」）；写入/复制都带 `lastCommitted` 维护。
- 新增 drawable：`bg_ime_card`（白底细线）/ `bg_ime_key`（米底）。
- **输入法改名**：`ime_label` / `ime_subtype_label` → 「简输入」（见上一节的风控理由）。

**刻意不放**：发送按钮、连点下一个、切换会话 —— 理由写进 `buildPanel()` 的 KDoc。

**布局踩点**：右列原本想用 `weight=1` 等分高度，但父容器是 `wrap_content`，
权重高度可能被算成 0（整列不可见）→ 改成自然高度：三格 ×(10+10+行高)+两道 8dp ≈ 118dp，
正好和左边三行网格等高。左侧因此从 2 行改成 3 行（第三行通栏放「打开 App」）。
