## 「同一句连点生成结果相同」+ 输入框叠加（commit d1d6a7e）

用户截图：输入框是 **「怎么说怎么说怎么说」** —— 三遍叠在一起，状态行还停在上一轮。
两个独立问题叠在一起：

### ① 输入框叠加（bug 级）
`InputConnection.commitText` 是**在光标处插入**，不是覆盖。
`TextWriter.write(replaceExisting=false)` → `ime.commit(text, replaceFirst=false)`，
所以连点三次就是三份追加。

修法：`AutoReplyImeService` 记住 `lastCommitted`，写新草稿前调 `clearOwnDraft(ic)`：
只用 `getTextBeforeCursor` 读回，**只有当框里内容以 lastCommitted 结尾时**才 `deleteSurroundingText`。
- 用户点发送后 App 清空 → `verifyWritten` 把 lastCommitted 置 null
- 用户自己接着打字 → 不满足 endsWith → 一个字不动
满足"连点不叠加"的同时守住"绝不覆盖用户输入"这条底线。

### ② 同一条消息重复生成结果相同
`DrillReplier.reply(persona, last.text, turns.count { it.fromOther })` ——
round 只由"对方说过几句"决定，**同一条消息重复生成时它根本不变**，
`pick()` 的索引也就不变 → 三次都给同一条。

修法：`AppConfig.drillNudge`（每生成一次 +1，持久化），
`pick(pool, seed, round, nudge)` = `(hash + round*7 + nudge*13) % size`；
样例轮换 `sameQ[floorMod(round + nudge, size)]` 也掺进去。
真实模型不需要（每次本来就不同），只在演练分支自增。

### 验算
`tools/verify_drill_pools.py` 加了【3】连点场景：
同一条「你约？一小时两张」+ 同一 round，nudge 0..5 → 6 条全不同；
邀约场景 nudge 0..3 → 4 条全不同。
