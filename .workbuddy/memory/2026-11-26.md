## 详细人设（小陈大夫）审查与落地

用户给了 `详细人设.txt`（2419 字），目标是回复一致性 60~80%，并要"热插拔"。

结论：**详细 ≠ 像**。这份是"资料包/业务定位"，缺对话样例。已产出
`人设-小陈大夫.json`（可粘到设置页「人设 JSON」，拼装后 system ≈1078 字 / ≈770 token）。

关键事实（写代码时要记住）：

- `tone.length` 是**死字段**，全项目没人读；真正的长度开关是 `config.maxReplyChars`
  （默认 35），`ReplyEngine.clean()` 在 `maxReplyChars * 2` 处**硬截断**。
  所以文件里 80~82 字的「参考话术」照抄会被砍在半句。
- `taboo_words` 是输出侧**命中即丢弃重写**，不能放 `AI` 这种泛词（会误杀）；
  替换关系（不说做 AI → 说智能工具）要写 `rules`。
- `boundaries` 是输入侧"对方说到就不回"，别把输出约束（不接诊/不开处方）塞进去。
- `temperature` 写死 0.8（`LlmClient:83`）。一致性不够时可考虑降到 0.7，但会牺牲变化。
- 热插拔**已经存在**：`PersonaPresets`（人设预设，同时切 personaJson + 本地编辑）
  + 输入法面板第二页一键切。操作顺序：先粘 JSON → 再「新建预设」（新建 = 当前副本）。
- 缺的只有一个"从 .txt/.json 文件导入"入口（目前只能粘贴）。

一致性建议：样例 12 条起（用自己的真话改写）、事实卡锁死、8 条行为准则、
盲测法（20 条真实回复混 20 条生成，猜中率 <40% 即算像）。

## 人设预设改成整套切换（已实施）

用户反馈：话术管理的人设预设只能换「情况/样例/准则」，换不掉身份，
每次还要回设置页重粘 JSON。

根因：`PersonaStore.Override` 里没有 identity；预设 body 虽然存了 `personaJson`，
但**设置页自由文本那条路径根本不进 body**，而且页面里也没有编辑身份的入口。

改法（不新增第二个真相）：

- `PersonaStore.Override` 加 `identity: String?`（null = 用外层），
  `load/save` 同步；`save()` 多一个 `identity: String = ""` 参数。
- `PersonaLoader` 新增 `base()`（只算外层，不含本地编辑）；
  `resolve()` 合并 `identity = ov.identity ?: builtin.identity`。
- `PersonaActivity` 新增「我是谁」段（多行 EditText，maxLines 8 / minHeight 112）。
- **关键细节**：保存时和 `base().identity` 比对，一样就写空串（不覆盖）——
  否则第一次保存就把外层 JSON 的身份固化成覆盖，以后改设置页不生效。
- 预设 body 存的就是 override 原样（`readRaw/writeRaw`），所以切换自动带上身份。

验证：precheck 9 步全过。未编译；真机待验「切预设 → 名字/年龄跟着换」。

## CI 第一轮：漏 import + precheck 第 6 步其实一直是瞎的

推上去后 CI 报 `MainActivity.kt:213 Unresolved reference: NotifyContext`。
`NotifyContext` 是并行会话加的通知兜底用的，import 没跟上；precheck 第 6 步报"通过"。

两个 bug，第二个更严重：

1. `tools/check_imports.py` 的 KNOWN 表是**手写清单**（注释还写着"新增类记得加"），
   `NotifyContext` / `ClipboardPeerText` / `ConversationMemory` / `PersonaPresets` /
   `ChatLogStore` / `TalkStyle` 全都不在表里 → 从没被检查过。
   已改成扫源码自动发现**第 0 列开始**的 class/object/interface/typealias（47 个），
   同名跨包的置 None 跳过（避免误报）。
2. `strip_noise()` 分三条正则依次去注释，被 `"接口地址 https://api.deepseek.com/v1"`
   里的 `//` 带偏：行注释删到行尾时把字符串的收尾引号一起删了 → 引号变奇数 →
   删字符串那条正则把后面几百行配成一对 → **整段代码被吞，使用位置在 src 里消失**。
   所以即使把类名加进表也查不出来。已改成字符扫描（同时支持 Kotlin 嵌套块注释、
   字符字面量；字符串遇换行就收手，宁可少删不吞代码）。

验证方式（可复用）：临时删掉那行 import → 检查器必须精确报出
`MainActivity.kt: 用了 NotifyContext 但没有 import` → 恢复后再跑必须零输出。
教训：**凡是"按正则逐层剥离"的静态检查，要先用"含有 `//` 或引号的字符串"验证一次**，
否则它可能整体失效而仍然打印"通过"——这种绿色比报错更危险。

## 人设导入 + 内置（已实施）

用户问"小陈 JSON 提交了，但装上的 App 里没有可直接用的人设" —— 对，之前没内置。
根目录的 `人设-小陈大夫.json` 不在 assets 里，也不会自动进预设。

1. **`PersonaPresets.seedBundled()`**：首次启动把 assets 的 personas 目录里每份 JSON
   装成预设，写 `seeded: true` 只装一次，**不激活**（不悄悄换用户的号）。
   调用点：`MainActivity.onCreate`（启动即有，输入法面板也能选）+ `PersonaActivity.onCreate`。
   内置文件：`app/src/main/assets/personas/小陈大夫.json`。
2. **「＋ 从文件导入 JSON」**（话术管理）：ACTION_OPEN_DOCUMENT（SAF，免存储权限），
   读文本 → `parsePersonaText()`（认完整 persona，也认 `{personaJson, override}` 形态；
   去掉 `_` 开头字段；identity / 样例 / 情况 / 准则全空则拒绝）→
   `insert(activate = true)` 生成新预设并切过去，重名加「（2）」不覆盖。
   导入时 override 写 `{}`：新 JSON 自带样例/准则，留旧覆盖会串味。

`insert()` 是新的通用入口，`createFromCurrent()` 保持不变（它复制当前这份）。
写入顺序：先 persist 预设档案，再写 override + personaJson 两层。

踩坑：KDoc 里又写了 `assets/personas` 加斜杠星号 —— precheck 第 7 步当场报"注释嵌套"。
