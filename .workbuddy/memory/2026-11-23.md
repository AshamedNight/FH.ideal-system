## 人设预设（PersonaPresets）

用户诉求：多份预设人设，同一时间只能勾选一份。

**关键设计决定**：一份预设存**两个来源**，不只存话术三件套。
- `personaJson`（设置页那段 JSON：身份/语气/禁忌词）
- `override`（`user_persona.json`：情况/样例/准则）

只换后者 = "怎么说话"变了但"我是谁"没变，而多号之间最容易露馅的正是身份。
切换 = 两份一起写回，`PersonaLoader` 一行没改。

- 档案柜：`filesDir/persona_presets.json`，`{active, presets:[{id,name,body}]}`
- 唯一性靠 `active` 字段，不靠界面单选框（界面只是投影）
- **存任意一页都自动快照**：`PersonaActivity.persist()` 和 `SettingsActivity.save()` 都调
  `snapshotActive()` —— 漏了会"切走再切回把改动还原"
- 界面用 `● / ○` 而不是 `RadioButton`：RadioButton 点击会自己翻转选中态，
  和"点当前那份什么也不发生"冲突
- 最后一份不能删；删掉生效那份自动回落

**验证**：`tools/verify_presets.py` —— 源码不变量核对 + Python 复刻规则跑边界。
过程中抓到我自己的一个**测试断言**写错（`create` 之前会先快照，所以第一份内容已经变了），
不是代码错。这类"复刻测试"要先想清被复刻的副作用的顺序。

## 他趣通知截断 + 「下一个未读」认不出 + 跨平台乒乓

### 1. 他趣通知只有预览（「…你平时是不是特…」）
通知栏收起态只给一行预览。全文可能在：`Notification.EXTRA_MESSAGES`（MessagingStyle，
完整消息数组）/ `EXTRA_BIG_TEXT`（展开态）/ `EXTRA_TEXT`（预览）。
**改法**：三个来源都读，取最长；昵称优先用 MessagingStyle 的 `sender`。
若三者都短，那就是通知本身被截断，取不到 —— 只能读聊天页或 OCR，不要承诺。

### 2. 「下一个未读」认不出 → 连点不往下走
真机截图里那个是**纯图标圆形按钮**（红点 + «»），`text` 为空。
而心遇配置只有 `textContains "下一个未读"`、同城是 `viewId tv_next` ——
心遇那条必然失败；同城那条如果 id 改版也会失败。
**改法**：
- `Selector` 新增 `contentDescContains`（图标按钮的唯一线索常是无障碍描述）
- 两个平台 nextUnread 都扩成四级：viewId → 文字 → 描述含「下一个」 → 文字「>>」
- 心遇补 `viewId tvUnreadRemind`（老 dump 里就是这个 id，文字是"下一个未读>>"）

### 3. 两个平台之间来回弹
`platformHops` 有上限但会让"心遇→同城→心遇"发生一次。
**改法**：加 `visitedPkgs`（每轮连点清空），绕回已去过的平台直接 `stopBatch` 并说明原因。

### 4. 读空没线索
`NodeQuery.emptyDiagnosis()` 一句话写出「选择器没命中 / 全树 N 个节点 / 前几个带文字的 id」，
`ReplyRunner` 在读空时 `service.logAuto(...)`（`logAuto` 因此从 private 改 public）。
他趣这种 `profile.message` 为空的平台则直接提示"只能等通知触发"。

**待验证**：通知全文是否真能拿到（MessagingStyle 不一定有）；
心遇读空的真实原因要看首页日志那一行。
