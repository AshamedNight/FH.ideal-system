# 2026-11-21

## 诊断：为什么"只能打招呼、回复很少"

结论：**当前测试只覆盖了漏斗第一道门，且缺埋点 ⇒ "回复少"无法归因。**

### 代码层面的实证

- `ReplyFlow` / `MainActivity` 里**没有任何持久化统计**，trace 只在内存里、下一次
  `decide()` 就被清空 → 用户手里只有一个"感觉回复少"，没有回复率这个数字
- `ReplyEngine.generate()` 里 `iSaidAlready = turns.any { !it.fromOther }`：对方从不回，
  这个值永远是 false ⇒ 每轮都命中固定开场白分支，**模型续聊 / 必要性判定 / 精力 /
  话术风险这些层从来没被真实数据触发过**
- 开场白走 `chunked(3)` + SentenceSplitter 拆 3 条连发。未回复情况下连发 3 条，
  是平台风控最容易标记的模式之一（发送数 >> 接收数且集中同会话）
- `AppConfig` 里**没有发送时段控制**（`timeOfDay` 只影响模型措辞，不影响发不发）

### 归因结论（按杠杆排序）

1. 资料层（头像真实性 / 距离 / 签名 / 照片数）—— 最大，且现在完全没管
2. 人群层（发给谁：在线、最近活跃、资料完整度）—— 很大，"精选 10 个"远胜"群发 100 个"
3. 时机层（20:00–23:30 / 12:00–13:30）
4. 内容层（第一句）—— 固定模板是回复率最低的一类；有效第一句必须引用对方资料里的细节
5. "固定开场白"和"高回复率"是两个互斥目标，现在是两个都想要 ⇒ 低回复 + 仍在花钱

### 下一步候选（等用户选）

- 加最小埋点：发出时间 / 会话 / 首句 / 话术分组 → 24h 回复率，首页显示
- 开场只发 1 句（去掉 chunked(3) 连发）+ 加活跃时段开关
- 个性化第一句：只对高意愿目标改用模型从对方资料生成

## 已落地：开场白改成「钩子库 + 槽位」（commit 97a89ea）

用户提议"20 条带钩子的开场白轮换"，做之前发现两个致命前提问题：

1. **旧轮换是假的**：`idx = abs(对方消息.hashCode()) % groups.size` —— 所有说「你好」
   的人 hashCode 相同，永远落到同一组，20 条库实际只用得到一两条。
   已改成 AppConfig 里持久化的 `greetingCursor` 游标。
2. **20 条纯手写句仍是"罐头"**：聊天页只能读到 3 样东西 —— 昵称、对方原话、时段。
   所以做成「模板 + 槽位」：`{昵称}` `{原话}` `{时段}`。
   槽位填不上就跳过该条，绝不把 `{昵称}` 字面量发出去（纯数字昵称也算填不上）。

其它连带改动：
- 去掉 `chunked(3)` 三句连发 → 一条库项 = 一条消息
- `Result.Draft.single` / `Outcome.Fill.single` 新字段：库内句子**不再过
  SentenceSplitter**。否则「做手工做到现在，你有上瘾的事没」会被按逗号拆成两条，
  用户只发第一条时问句丢失，开场白直接失效（SOFT 拆点两边都 ≥5 字就触发）
- 新增 `core/llm/GreetingHooks.kt`（20 条内置库 + fill 逻辑）、
  设置页「载入内置 20 条钩子模板」按钮
- 抽 `hourAndPeriod()`：时段词原有两个副本会走偏

验证方式：`tools/verify_greeting_hooks.py` —— **regex 直接从 .kt 源码里读 DEFAULT 那 20 条**，
不手抄，避免脚本和实现走偏；再复刻 fill + 游标逻辑跑 4 组断言。
配合 `tools/precheck.sh` / `check_imports.py` / `check_encoding.py` 全绿。

## UI 现状诊断（用户反馈"像没开发完的测试 demo"）

根因不是缺素材，是**零层级**：
1. 字号只有三档（22/14/12），标题和正文挤在一起，扫不出重点
2. 所有操作都是全宽 Material 默认按钮，视觉权重完全相同 → 不知道先点哪个
3. 状态是三行纯文字（`status_service` / `status_notify` / `status_level`），
   没有「完成 / 未完成」的视觉信号（该用色点）
4. 主界面把调试功能（界面抓取、链路自检）和日常操作平铺在一起，没有分组
5. 间距随手（4/6/8/12/16 混用），没有 4dp 栅格
6. 真正的重灾区其实是**设置页**：20+ 字段全是「11sp 灰标签 + 输入框」直线排列

**硬约束：零第三方依赖**（不引 androidx / Material / Compose）→ 只能用系统主题 + shape drawable + 系统字体（sans-serif / monospace）+ letterSpacing。
高级感只能靠排版、留白、层级、克制配色实现。

已给三个方向（尚未实施，等用户选）：
- **A 深色仪表盘**：深绿顶栏 + 状态胶囊 + 白卡片分组 + 深色终端日志。改动中。
- **B 极简白**：细线分隔 + 27sp 大标题 + 加字距小标签 + 胶囊按钮。改动最小。
- **C 纸感工单**：米白纸底 + 01/02/03 编号段落 + 虚线分隔 + 小圆角方块按钮。改动中大，独特。
- 倾向：**B 做底 + A 的状态胶囊**，并必须同步重排设置页，否则两页风格打架。

## 「粘贴出来还是老开场白」（commit 290e024）

用户反馈：设置页里 20 条新库明明在（截图可见），但长按粘贴拿到的还是旧话术。

**证据链**：截图里剪贴板 `150/150`，条目含「突然有点想认识你。」「然后呢」「我懂你说的」「Hello」。
- 「突然有点想认识你」是 `persona.json` few_shot 里 `q=你好` 的答案（不是开场白库里的句子）
- 带**句号**：只有旧版 `joinToString("。")` / 旧版 DrillReplier `answer + "。" + OPENERS` 才produce得出来；
  新版开场白是单条、DrillReplier 用 `\n` → **新版不可能生成这句**
- 结论：那是旧版跑演练模式时写入剪贴板的**历史条目**

**两个真实缺陷（已修）**：
1. `AutoReplyImeService.verifyWritten` 里写剪贴板**不回读**，`setPrimaryClip` 失败不抛异常
   （Android 10+ 后台限制、部分 ROM 剪贴板满 150 就拒收），界面照样报"草稿已放剪贴板"。
   → 新增 `copyDraft()` 回读校验；状态行改为「剪贴板：<草稿前 12 字>」或「剪贴板没写进去」
2. 「载入内置 20 条钩子模板」只 `setText` 输入框，**`config` 要等滚到最底点「保存」才落盘**。
   用户载入完就退出去 → 一直是老话术。→ 改成载入即 `config.greetingLines = DEFAULT` 立即生效

**排查顺序（给他自证用）**：清空剪贴板历史 → 重新触发 → 看状态行是否显示新库开头 → 重装后重新点一次「载入」。
