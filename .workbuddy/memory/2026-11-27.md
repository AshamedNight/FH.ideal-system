## "生成和下层日志对不上" —— 三个不同的原因，不是一个

用户截图（他趣）：判定链写 `④ 生成：第 1 次成稿`、草稿「刚忙完，累得不想动。你忙不忙」、
`填入：已通过输入法写入`，但下面「草稿」行是「换个话题吧」；
而且 `本次：输入 0 / 输出 0 token`、`本地估算：约 0 token 输入`。

关键判据：**本地估算也是 0** → 这一轮根本没构造请求。走的是
`ReplyEngine.generate()` 里"开场白 / 话术库"那条：`greetingEnabled && !iSaidAlready && peerOpenedWithGreeting`
时直接返回库里的句子（tokens 0、attempts=1），但判定链只写"第 1 次成稿"，不写来源。

另外两层"对不上"：

1. 上层那块是 **MainActivity「试填」的历史结果**，不会跟着输入法面板的动作刷新；
   下层「草稿」是输入框**实时**内容。两张纸来自不同时刻。
2. `commitText` 只写进"当前绑定的 InputConnection"。面板/首页浮在目标 App 上时
   这个连接可能还连着上一个输入框 → 写进别处、目标框还是旧内容，日志却报"已写入"。

修了四处：

- `ReplyEngine.Result.Draft` 加 `source`（模型 / 话术库 / 开场白（多条）/ 开场白库 / 演练），
  由 `sourceLabel()` 判定 mock；`ReplyFlow` 的 ④ 变成 `第 N 次成稿 · 来源 X`。
- `AutoReplyImeService` 记 `boundPkg`（onStartInputView 取 `info.packageName`），
  `commit(text, replaceFirst, expectedPkg)` 先比包名：不一致就**挂起**（pendingPkg）不硬写；
  `flushPending` 也按 pendingPkg 拒绝串到别的 App。
- `TextWriter` 传 `expectedPkg`，包名不符时给出准确提示「先点一下这个 App 的输入框」。
- 试填输出头加时间戳 `判定链（试填 09:39:12）`；面板生成后 250ms 再刷一次草稿行
  （commitText 的 selection 回调有时比回调晚一拍）。

教训（值得复用）：**日志里"0 token"要能和"没调模型"对上号**。
只要 UI 上有"成稿"这种中性词，用户就会默认是模型写的，然后拿它去和别处对账。
凡是"本地库/快捷路径"，输出必须自报家门。
