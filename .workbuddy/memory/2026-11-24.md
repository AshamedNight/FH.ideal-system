## 爱聊第二次 dump：我方消息 id 是 `#right_iv_text`，不是 `#right_tv`

用户发完一条消息后重新抓了聊天页（226 节点 / 可编辑 1）。关键行：

```
LinearLayout #right_iv_text_box [147,895,936,1048] noimp
  TextView #right_iv_text_readState_iv "未读" [147,952,229,991] click   ← 角标，不是消息
  FrameLayout [229,895,915,1048] noimp
    TextView #right_iv_text "你觉得你性格内向还是外向" [229,895,915,1048] click
```

**两个必须记住的事实**：

1. **我方文字消息的真实 id 是 `#right_iv_text`**（`#right_tv` 只是旧版变体，
   这条会话里是 hidden）。第一次 dump 没有我方文字，所以只写了 `right_tv`，
   第二次才补全。现在 `viewIdIn = left_iv_text,right_iv_text,right_tv,left_tv`。
2. **我方气泡左边缘 229 < 屏幕三分点 360** —— 纯坐标判定会把它当成"对方发的"，
   于是「最后一条是对方」判断直接错。上次加的 id 前缀规则（`left_`/`right_` 优先于
   坐标）在这里被真机证实是必需的，不是保险。

另有 `#right_iv_text_readState_iv "未读"`（左边缘 147、文本「未读」）——
不在选择器里，**千万别加**，否则每条我方消息后面会多读出一条「未读」当对方消息。

**验证方式（可复用）**：写个小脚本按 profiles.json 的 viewIdIn 从 dump 文本里
regex 抽消息行，复刻「id 前缀 → 坐标」判定，打印 `对方/我方 + bounds + 文本`。
本次结果：`对方 [165,371] 你好` / `我方 [229,915] 你觉得你性格内向还是外向`，
`最后一条来自对方=False`、`我方条数=1` —— 与实际一致，且此时不生成是正确的
（最后一句是自己说的）。

**教训（值得记）**：dump 只能证明"当时屏幕上有的东西"。第一次抓的时候我方一条
消息都没有，就以为 `right_tv` 是我方 id，实际是 `right_iv_text`。**凡是"左右两侧"
的选择器，都要等两侧各有至少一条消息再抓**，否则只能算半份配置。
（这次没造成误读，因为 viewIdIn 里同时留着 left_tv/right_tv，读不到就跳过。）

## CI 挂在一个重复声明上：`var llmProxy` 写了两份

用户推上去后 Kotlin 编译失败，报的是：

```
e: AppConfig.kt:19:65 Missing '}'
e: CaptureService.kt:176:41 Unresolved reference: LEVEL_FILL_ONLY
e: ...（level / batchSize / targetPackages / clipboardOnly 全 Unresolved）
```

**真因**：加分发模式时新写了一个带 `distributionEnabled` 判断的 `llmProxy`，
却忘了删文件后半部分原来那个 —— 同一作用域里 `var llmProxy` 声明了两次。
报错位置全在别处，是因为**整个文件解析失败**，所有调用点跟着变 Unresolved。
（`Missing '}'` 指向第 19 行纯属误导：括号其实是平衡的。）

**修复**：删旧的那份，把两段注释合成一份（保留"只给模型请求用、分发模式强制清空"）。

**新增 precheck 第 9 步 `tools/check_dupes.py`** —— 这类错误前 8 步一条都查不到：
括号平衡、import 齐全、字符串闭合，只是名字重复。

写这个检查踩的坑（都修了，值得记）：
- 第一版把**函数体内的局部变量**也算进去 → 满屏误报（`val t`/`val cfg` 在不同函数里）。
  改成只查**类/对象体成员**，并且要求声明深度正好是容器深度 +1。
- `sealed class` 的子类用主构造器写属性（`data class Fill(` 后面没有 `{`），
  被算进了父类作用域 → `Fill.val text` 和 `Hold.val text` 误判。
  补了"构造器作用域"：遇到 `class X(` 且本行无 `{` 时单开一个作用域，括号配对后关闭。
- 跨行参数表的两个重载（`fillOnly(root,…)` / `fillOnly(roots,…)`）参数串都被截成 `"("` → 误判。
  改成参数表跨行时按行号当唯一键（宁可漏报）。

验证方式：`git show <坏提交>:AppConfig.kt > _broken.kt` 喂给脚本，
必须精确报出 `354 重复声明 var llmProxy（第 320 行已声明）`；全量跑必须零输出。

**顺手补的漏洞**：分发模式下 `llmModel` 原来仍可被成员改，改成上游不认的名字会一律 400，
看着像中转坏了。现在 `distribution.json` 可填 `model` 钉死它（`AppConfig.llmModel` getter 覆盖），
设置页在分发模式下不再渲染模型名输入框，`save()` 里四个模型字段整段跳过
（`textOf` 对不存在的输入框返回空串，无条件写回等于清空配置）。

## 但真正让 CI 挂的不是重复声明 —— 是注释里写了个「斜杠星号」

修完重复声明再推，CI 报错一行没变。截图底部那条被裁掉的错误才是关键：

```
e: AppConfig.kt:484:1 Unclosed comment
```

**真因**：我在 `dist` 的 KDoc 里写了「precheck 第 5 步本来就会校验 assets/星号json 是否合法」
（原文用的是斜杠加星号）。那一对字符是块注释的开头，而 **Kotlin 的块注释支持嵌套** ——
于是第 26 行又开了一层，从那里到文件尾全成了注释。后果：
- 所有属性都不存在 → 满屏 `Unresolved reference: level / targetPackages / clipboardOnly`
- 类没闭合 → `AppConfig.kt:19:65 Missing '}'`（位置纯属误导，那是解析器停下的地方）
- 文件尾 → `Unclosed comment`

**教训（这次最值钱的一条）**：CI 报「Missing '}'」「Unclosed comment」+ 满屏 Unresolved 时，
第一个该查的不是括号，而是**注释里有没有那个斜杠星号组合**（Kotlin 里它嵌套）。
判据很快：数 `/*` 与 `*/` 的个数，或直接跑 precheck 第 7 步。

**已加进 precheck 第 7 步**（`tools/check_encoding.py` 新增 `scan_comments`）：
按 Kotlin 规则扫全项目，报三类 —— 注释里嵌套开新注释（带上下文片段）、多余 `*/`、
文件尾还有未关闭的层。用坏提交 `39dde80` 验证：精确报出第 26 行的
`assets/…json`（嵌套）。

**踩的第二个坑**：修这行时，我在解释文字里又写了一遍那个组合 → 检查立刻报警，
只好改成「斜杠星号」这种文字描述。**这个组合在注释里就是禁区，连解释都不能写。**
