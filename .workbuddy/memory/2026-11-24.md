## 爱聊第二次 dump：我方消息 id 是 `#right_iv_text`，不是 `#right_tv`

用户发完一条消息后重新抓了聊天页（226 节点 / 可编辑 1）。关键行：

```
LinearLayout #right_iv_text_box [147,895,936,1048] noimp
  TextView #right_iv_text_readState_iv "未读" [147,952,229,991] click   ← 角标，不是消息
  FrameLayout [229,895,915,1048] noimp
    TextView #right_iv_text "你觉得你性格内向还是外向" [229,895,915,1048] click
```

**两个必须记住的事实**：

1. **我方文字消息的真实 id 是 `#right_iv_text`**（`#right_tv` 只是旧版变体，
   这条会话里是 hidden）。第一次 dump 没有我方文字，所以只写了 `right_tv`，
   第二次才补全。现在 `viewIdIn = left_iv_text,right_iv_text,right_tv,left_tv`。
2. **我方气泡左边缘 229 < 屏幕三分点 360** —— 纯坐标判定会把它当成"对方发的"，
   于是「最后一条是对方」判断直接错。上次加的 id 前缀规则（`left_`/`right_` 优先于
   坐标）在这里被真机证实是必需的，不是保险。

另有 `#right_iv_text_readState_iv "未读"`（左边缘 147、文本「未读」）——
不在选择器里，**千万别加**，否则每条我方消息后面会多读出一条「未读」当对方消息。

**验证方式（可复用）**：写个小脚本按 profiles.json 的 viewIdIn 从 dump 文本里
regex 抽消息行，复刻「id 前缀 → 坐标」判定，打印 `对方/我方 + bounds + 文本`。
本次结果：`对方 [165,371] 你好` / `我方 [229,915] 你觉得你性格内向还是外向`，
`最后一条来自对方=False`、`我方条数=1` —— 与实际一致，且此时不生成是正确的
（最后一句是自己说的）。

**教训（值得记）**：dump 只能证明"当时屏幕上有的东西"。第一次抓的时候我方一条
消息都没有，就以为 `right_tv` 是我方 id，实际是 `right_iv_text`。**凡是"左右两侧"
的选择器，都要等两侧各有至少一条消息再抓**，否则只能算半份配置。
（这次没造成误读，因为 viewIdIn 里同时留着 left_tv/right_tv，读不到就跳过。）
